## 3. Bugs and gaps found (file:line)

Routing / prompt assembly (director.py, brain.py, routing.yaml)
- D1. **Envelope bypass on forced mode.** `variety()` (director.py:80-82) validates `--mode` only against `brain.MODES`, not `brain.style_envelope(aud)["modes"]`. older_adult drama is accepted and then fails lint forever. Fix: refuse with SystemExit when `force_mode not in env["modes"]` (and in `repair()`, director.py:314, re-route to `env["modes"][0]` or stop).
- D2. **Self-contradicting prompt.** director.py:106 says "Set `direction.mode` to exactly '{mode}'" even when the envelope (line 103) forbids it. This is fixed by D1.
- D3. **Stale bridge list.** `RENDERABLE_BRIDGES` (director.py:63-64) still lists 3 bridges and tells the writer "others are not yet supported", while lint.py `_BRIDGES` says all six render (Episode.tsx, 2026-10-05). The director is steered away from freeze-rewind, j-cut and question-card. Fix: import one constant from lint (or a shared module) and use it in both places.
- D4. **The writer never sees the `direction` / `shot` / `continuity` shapes.** episode.schema.json is not in the prompt, script_template.yaml has no `direction` entry, and the worked example (ep01-interest-rates-v2) has no direction or shot. Result: invented keys (`cold_open.beats`, `seconds`, `style_segments` as strings, `dialect` instead of `medium`), with `duration_s`, `scene_ids` and `archetype` missing in 4 of 4 drafts. Fix: add a compact `direction`/`shot`/`continuity` skeleton (from the schema) to the prompt, plus one directed worked example.
- D5. **Archetype recipes, lens parameters and bridge cards never load.** `system_prompt` calls `brain.pack("shotlist", mode, aud)` with no `arch`/`lens` (director.py:107). routing.yaml `shotlist` (lines 15-25) names no `arch-<type>` or `lens-<id>` cards, and the `mode-bridge-*` cards are only in the `edit` pack (line 29+). The director sees archetype and lens *names* (arch-router, envelope) but not their recipes, duration ranges, kids_variant or parameters. Fix: two-step pack: after `choose_mode`, have a cheap call choose archetype + lens + bridge from the envelope, then load exactly those three cards (that is what `pack(arch=, lens=)` was built for).
- D6. **`brain.render` drops `kids_variant`, `duration_s`, `bridge_out`** (brain.py:64-81 renders only rules/ai_safe/avoid/recipe/anchor/test). Even when an archetype card loads, the kids softening text is invisible. Fix: render `kids_variant` when audience is kids, plus `duration_s` and `bridge_out`.
- D7. **Hailuo dialect not loaded; camera syntax conflict.** director_prompt.md:62 says use `[Camera command]` brackets from `craft/dialects/hailuo.md`, but the dialect file is never injected (`brain.dialect` is unused by director.py). Dialect section 12.6 says "until the A/B, use (b) natural-language camera sentences", while lint `camera_command_syntax` (lint.py ~217-226 + qa_checklist.yaml:166) warns when brackets are absent. Fix: resolve via the paid A/B (section 4); until then make lint accept either form.
- D8. **`--topic` grounding is junk.** `topic.source_urls = [i["url"] for i in items[-10:]]` (director.py:230): the last 10 items of a Google-News search on the whole topic sentence were Teslarati, Sun Sentinel launch schedule, Starship Flight 13, Artemis II, Perseids and a Musk/Gates story. There were no NASA or Wikipedia pages, so the physics claims cite a Teslarati redirect, which passes `lint.provenance` (URL was fetched) but supports nothing. Fix: add `--source URL` (repeatable, fetched like news items), allow reusing an existing episode's `sources`, rank search items by relevance, and require at least one primary or reference source per mechanism step before writing.
- D9. **Google-News redirect URLs are ~200 chars**; the writer mis-copied them (ep12 `claims_urls_in_catalog` x2). Fix: give each source a short id (`S1`...) in the prompt and map back to the URL in code.
- D10. **Episode id allocated before the slow write, not reserved.** `next_id` (director.py:252) uses the episode list loaded at start, and the directory appears only ~15 min later. Two concurrent runs get the same id. I had to serialize runs by hand. Fix: create the directory (status `idea`) immediately after choosing the id, or lock `out/director.lock`.
- D11. **`sources.json` written only in `finish()`** (director.py:291). A crash or timeout leaves a draft whose `--repair` has an empty catalog (all claims become `claims_urls_in_catalog` errors). Fix: write `sources.json` in `_save_draft`.
- D12. **Repairs re-send the 28k-token system prompt + full episode for mechanical fixes** (director.py:282). Sentence-length, hook-length and word-count problems oscillate. Fix: deterministic fixers or a scene-scoped repair (send only the failing scenes plus their rules; use `run.py scene ... set` semantics) and keep the full-JSON repair for analogy/claim errors.
- D13. **older_adult card has no `illustration_style`** (direction/audiences/older_adult.yaml). The prompt rule "copy illustration_style EXACTLY" has nothing to copy.

Lint (lint.py)
- L1. **Crash on any schema-invalid draft in the registry.** `lint.run` loops over all episodes and reads `o["scenes"]` (lint.py:425-426). One bad draft breaks lint for every episode and every session. Fix: `o.get("scenes") or []`, and wrap per-episode reads in try/except. Separately, `_save_draft` should not save a draft without `scenes` into `episodes/` (keep it in `out/<id>/draft_invalid.json`).
- L2. **Cold-open checks are conditional on optional keys.** `dir_cold_open_present` only checks that `cold_open` is truthy (lint.py:294). Budget, audience cap, scene order and wide-first only run when `duration_s` / `scene_ids` exist (lines 286, 298, 311, 322-325). All four drafts omitted them, so none of those checks ran. Fix: in drama modes make `archetype`, `duration_s`, `bridge`, `scene_ids` required (schema `required` under an `if mode in (cold-open-drama, hybrid)`).
- L3. **Dialect only checked through a declared `style_segments`.** ep10 ("realistic, cinematic lighting") and ep13 ("photographic style" for older_adult, native only) slipped through. Fix: infer the segment dialect from prompt words (realistic, photographic, cinematic, shallow depth of field, 35mm) and error when the envelope is native-only, or when cinematic appears without a declared segment and bridge.
- L4. `shot.archetype` values are not validated (ep10 `demonstrate`); `skills_used` empty is not flagged in drama modes (ep12).
- L5. **No clip-length check**: `shot.duration_s` 8 on a 6 s H3 clip. Fix: compare against `providers.yaml video.init_args.duration`.
- L6. **No "narration before the bridge" check** (`mode-cold-open-drama` rule). Fix: warn when cold-open scenes carry narration beyond one in-scene line.
- L7. **No CJK/non-ASCII leakage check** in prompts (ep13 "镜头"). `prompt-leakage-sweep` is in the pack but not enforced. Fix: error on CJK codepoints in `prompt`/`keyframe_prompt`/`motion_prompt`.
- L8. `dir_mode_allowed` is invisible while any schema error exists (director.py:173-174 early return). Fix: run `_direction_checks` mode/envelope checks on the raw dict before the schema gate, or put the mode enum per audience into the schema.

Verifier (verify.py)
- V1. **`real-text-counts` treats `visual.term` stickers as image text** and fails the gate (blocker). Fix: strip `term`/`number`/`steps` overlay fields from the plan sent to the realism pass, or state in the prompt that they are renderer overlays.

## 5. Protocol (prepared, NOT run): paid H3 camera-syntax A/B

Question (hailuo.md section 12.6): on MiniMax-H3 `/v2/video_generation`, which prompt form gives the most faithful camera move and identity hold: (A) bracket tokens `[Push in] ...`, (B) natural-language camera sentence in the HF form ("The camera pushes in with small amplitude at slow speed toward ..."), (C) full Context-IR I2VA format (alignment line + `integrated_multimodal_description`, `overall_soundscape: N/A`, `non_diegetic_music: N/A`)?

Prerequisites: the owner approves the spend; the pay-as-you-go balance is confirmed; `providers.yaml video` stays `MiniMax-H3`, 768P, 6 s, `prompt_optimizer` unchanged across arms. Use a separate scratch episode (for example `ab-h3-camera`, status approved by the owner only), never ep01-ep13. One keyframe per prompt, made once with image-01 at 1152x2048 and reused by all three arms (the arms differ only in the text).

Prompts (one beat, one camera move each, positive phrasing, no text in frame):
1. P1, cinematic push-in (ep10 s1): capsule below a space station, sun camera-left. Move: push in, small amplitude, slow. Subject action: engine glow pulses, capsule drifts up toward the docking port.
2. P2, native storybook tilt-down (ep12 s1): maple tree in autumn colours, one red leaf detaches. Move: tilt down following the leaf, medium amplitude, slow. Tests whether the illustrated style holds.
3. P3, static mechanism hold (flat-vector diagram, an ep10 s5-like composition): station on an upper arc, capsule on a lower arc. Move: static shot; only the capsule moves along its arc. Tests unrequested drift, the most common failure for diagram clips.

Arms per prompt: A bracket, B natural sentence, C Context-IR. **3 prompts x 3 arms = 9 clips, 1 take each.**
Cost: 9 x 6 s x $0.08/s = **$4.32** (under the `max_clip_cost_usd: 6.0` cap). With 2 takes each (recommended for variance) it is 18 clips = **$8.64**, which needs a deliberate cap raise or two runs. Keyframes: 3 image-01 calls (price not in providers.yaml; small next to the clips). Optional free-or-cheap diagnostic: send the B prompt for P1 to `/v2/h3_context_ir` once to see how the hosted IR rewrites the camera clause. Check that endpoint's price first.

Per-clip mechanical checks (ffprobe; reject the clip from scoring if any fails):
```
ffprobe -v error -select_streams v:0 -show_entries stream=codec_name,width,height,r_frame_rate,nb_frames -show_entries format=duration -of json clip.mp4
ffprobe -v error -select_streams a -show_entries stream=codec_name,sample_rate,channels -of json clip.mp4
```
Expect: h264, width 768 and height about 1364-1366 (9:16, short side 768), `r_frame_rate` 24/1, duration 5.8-6.1 s, nb_frames about 140-146. An audio stream is expected (32 kHz stereo per the HF card; Remotion mutes it). Record the actual values in hailuo.md section 0 (first measured H3 output). Also extract the first frame (`ffmpeg -i clip.mp4 -frames:v 1 f0.png`) and compare it to the keyframe (SSIM >= 0.85 expected for I2VA).

Scoring (blind; a human looks at a contact sheet of 6 frames per clip plus the clip itself; arm labels hidden):
- Move obedience 0-2: right move type and direction (2), right type but wrong amplitude or speed (1), wrong or extra move (0).
- Unrequested motion 0-2: no drift, zoom or reframe beyond the asked move (2).
- Identity/style hold 0-2: subject and style match the keyframe through the last frame (2); for P2, the storybook texture stays.
- Artefacts: any text or glyphs, morphing, or mouth or lip motion = automatic 0 for that clip.
Success criteria: an arm wins if it has the highest total on at least 2 of 3 prompts **and** never scores 0 on identity. A tie between A and B goes to B (the dialect default, and readable). C is adopted only if it beats B by at least 2 points total, since it costs more prompt engineering and has a 7000-char adapter cut. Write the result into hailuo.md 12.6 and section 10, and change lint `camera_command_syntax` to match the winner (bug D7).
