# /episode - video pipeline operator

Never print, log or copy secrets from `.env` or `.secrets/`. Do not use git worktrees. Work on main.

## Verbs
- **list / "what's posted"**: `run.py list` (prints table, writes EPISODES.md). `run.py sync` pushes the table to the Google Sheet tab "Episodes" (the /videos page reads it).
- **new <topic> [format] [sponsor]**: first try the automated Director: `python run.py director --topic "<topic>" [--audience kids|curious_adult] [--format id]` (no topic = pick from live news; `--pick` lets the owner choose from the list, `--dry` only lists, `--choose N` picks a saved candidate). Every video needs at least one MiniMax Hailuo `clip` scene (lint-enforced). Look-and-feel rules live in `direction/DESIGN_SYSTEM.md`; after a render, read the contact sheet `out/<id>/contact*.png` and `render_qa*.json`. It writes a lint-checked draft; review it like any script. If it cannot be used, act as the director manually. Follow `direction/director_prompt.md` exactly (research with source URLs, pick format from `direction/format_catalog.yaml`, analogy rules from `direction/audience.yaml`, shots per `direction/shots.md`). Write `episodes/<id>/episode.json` with `status: "scripted"`, then `run.py lint <id>`; fix all errors. Show the user the script + shot list and the Director Notes. STOP: paid generation is blocked until `status` is approved (run.py enforces it).
- **storyboard <id>**: `run.py storyboard <id> [--json]` writes `out/<id>/storyboard.md`, a free generated scene-by-scene map (timing, format beat and word budget, the mechanism step / concepts / questions each scene carries, on-screen elements, shot facts, cost class, lint flags, director_notes). Read it when asked "why is this scene here" or before approving; never edit it, change `episode.json` instead.
- **manifest <id>**: `run.py manifest <id> [--json]` is a free plan of what a build would generate (voice lines, images, keyframes, clips) and the clip cost against the cap, using the real stage code with generation stubbed out. Show it to the user before `approve`. Only clip price is recorded in `config/providers.yaml`; other units are counted, not priced.
- **animatic <id>**: `run.py animatic <id> [--render]` writes `out/<id>/props.animatic.json`: the real `Episode` composition with placeholder cards where paid media would go (intent, what will be shown, shot facts, narration, duration). Review it in Remotion Studio (`cd remotion-app && npx remotion studio src/index.ts --props=../out/<id>/props.animatic.json`) before spending. No audio; the cold-open bridge is not simulated.
- **scene edit**: change one scene with `run.py scene <id> <scene-id> set <path> <value> --reason "why"` (or `unset`; `--dry` previews; `run.py decisions <id> [<scene-id>]` shows the log). It refuses edits that break the schema or add a lint error, refuses scene-id changes, refuses rendered/posted episodes without `--allow-rendered`, requires a real reason, tells you when `verify` went stale, and appends to `episodes/<id>/decisions.jsonl`. Prefer it to hand-editing `episode.json` so every change leaves a trail.
- **live runs / progress**: long commands (`director`, `verify`, `manifest`, `animatic`, `publish`, `<id> <stage>`) are recorded under `out/runs/<run_id>/` (meta.json + a live log tee). `run.py director-status` shows the latest Director run (stage, time waiting on the model, per-call durations); `run.py live` starts a read-only 127.0.0.1 server that the web UI's **Videos > Live runs** tab polls (steps, state, live log). Start `run.py live` before long runs if the user wants to watch them; tell them the tab address needs the app origin to be allowed (`LIVE_ALLOWED_ORIGINS`). Always run long Director/verify commands in the background with `python -u` and a long timeout, and check `director-status` instead of guessing.
- **brief + story gates (always for a new video)**: put the owner's questions in as `--brief "question 1|question 2|question 3"` (repeatable). The Director must answer each in its own scene, in order, and records `brief[].answered_in`. Lint then checks: every brief question answered (`story_brief_answered`), terms defined before use, no jumping back in time (`story_time_jumps`, or declare `chronology: forward` with `when` per scene), at most 8 spoken figures and 3 on-screen figures per scene, and text/number tiles at most 40% of scenes (error above 60%). `verify` adds a story editor pass that reads the storyboard like a first-time viewer (brief answered directly, order, concept explained, data dump). Pick scenes by the relationship they show: chart (change over time), timeline (sequence), forces (push against push), number (ONE headline figure), compare (two definitions), illustration/clip (metaphor or real footage). Cut figures, never the explanation, to fit the length.
- **identity**: information decides the look, not the audience. Every new audience episode needs its own `identity` (archetype, palette, fonts, shape, backdrop, motion, caption, term). The Director sets it when it saves a draft; for a hand-written episode run `run.py identity pick <id>` (`--dry` to preview, `--archetype`/`--info`/`--palette` to override, `run.py identity list` to see the catalog and what recent episodes used). It rotates against the last 5 episodes, so never pick a look by copying the previous episode's. Lint checks it (`identity_present`, `identity_contrast`, `identity_variety`, `identity_banned_default`). Setting an identity also sets `style.illustration_style`, so generated images change and will regenerate on the next build.
- **selfcheck**: `run.py selfcheck` (free, no paid calls) checks every episode against the schema, the lint gate, the QA checklist's enforcement claims and doc references. Run it after any edit to `episode.json`, the schema, `lint.py` or `qa_checklist.yaml`, and before `approve`. Exceptions to a lint rule go in the episode's `waivers[{rule, reason}]`, never in the rule's threshold.
- **verify <id>**: `run.py verify <id>` runs the verifier agents (analogy attack, claim support, comprehension test) and writes `out/<id>/qa_report.json`. Show the user the errors and the `unverifiable` claims that need a human spot-check. The Director already runs this inside its repair loop.
- **show before building**: before `approve`/`build`, show the owner the storyboard (`run.py storyboard <id>`), the identity (`run.py identity show <id>`) and the lint/verify results. A passing verify is the minimum, not the goal: read the storyboard as a viewer and check it answers the brief, in order, with explanation before numbers.
- **approve <id>**: only after the user clearly approves the script in chat -> `run.py status <id> approved`. For audience-declared episodes this is refused unless the QA report is fresh and passed (`--skip-verify` overrides; say so to the user if you ever use it).
- **build <id>**: `run.py <id> all` (tts, illustrations, keyframes, clips, props, render, carousel). Content-hash cache means only changed scenes regenerate. After render, make a contact sheet with ffmpeg and look at it before reporting; run lint; report honestly what you could and could not verify (you cannot hear audio).
- **revise <id> "<change>"**: edit `episode.json` (narration, prompts, terms), re-run lint, then `run.py <id> all` (only changed scenes cost anything). Keep status unless the change is large (then set back to `scripted` and ask for re-approval).
- **review ok**: when the user says the video is good -> `run.py status <id> reviewed`.
- **package <id>**: ensure `publish.youtube` (title, description incl. sources + "not financial advice" when relevant, tags) and `publish.instagram.caption` exist in episode.json; carousel exists; sponsor disclosure present if sponsor.
- **publish <id> <youtube|instagram>**: ALWAYS run the dry run first (`run.py publish <id> <platform>`), show the user exactly what would be sent, and only run with `--confirm` after the user explicitly says yes to that specific post. YouTube defaults to `--visibility private` (unverified API projects are forced private until Google's audit); never use `--visibility public` unless the user says so. Platform AI/synthetic-content labels are set at upload (YouTube `containsSyntheticMedia` is set by the uploader); no AI text is burned into frames (owner preference).
- **mark-posted <id> <platform> <url>**: add to `posts[]` in episode.json via registry, then `run.py sync`.

## Rules
- Honest reporting: say what is verified (rendered, lint result, frames viewed) vs unverified (audio quality, music taste, upload behaviour).
- Sponsors: follow `direction/sponsor_playbook.md`; spoken/visual disclosure + platform paid-promotion tool; AI-voice endorsement needs its own disclosure.
- Facts: every claim needs a source URL in `claims[]`/`sources`; mark unverifiable claims and keep them out of narration.
- Costs: image/voice are cheap; clips (MiniMax H3, about $0.48 per 6 s clip at 768P, verified on the vendor pricing page 2026-10-05; Hailuo-2.3 fallback about $0.28) are the main spend. Prefer illustration scenes; use clips for story beats only.
- Vendor repos in `video-pipeline/vendor/` and `reference/` are read-only study material. `reference/3b1b-videos` is CC BY-NC-SA: never copy its code into the pipeline. OpenMontage is AGPL: do not copy its files.
