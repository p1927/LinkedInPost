## 0. Method and honest limits

Evidence tags: **[V]** I cloned the repo (shallow, read-only, nothing executed) and read the README / SKILL.md head; **[M]** GitHub metadata only (`gh api` / `gh search repos`, 2026-10-05) plus the repo description; **[S]** web-search snippet or fetched summary only, not checked on a primary page; **[R]** craft consensus from memory, not fetched.

- GitHub star counts and push dates are from `gh` on 2026-10-05 and move fast. Licences are the SPDX value GitHub reports unless I say I read the LICENSE file.
- Clones lived in the session scratchpad. I never ran `install.sh`, `setup.py`, Python or shell scripts, and never installed an MCP server.
- Safety scan: I grepped all 25 clones for `curl|sh`, `base64 -d`, `sudo`, "ignore previous instructions" and "disregard ... instructions" patterns. Only hits were `sudo apt-get install ffmpeg` in two CI workflow files (cutcraft, awesome-seedance) and one Dockerfile (video-prompting-skill): benign. That is a pattern grep, not an audit. It does not prove a SKILL.md is clean, and I did not read every file in any repo.
- Much of the 2026 ecosystem is Chinese-language (AI short-drama / comic-drama on Douyin). Several top repos are mostly Chinese prose. I judged those by structure and metadata, not by reading every Chinese reference file. Translation risk is real for distillation.
- Star counts in this niche are inflatable and I cannot rule it out; the high-star Chinese repos (below) are plausible for that community but I could not verify organic growth. Treat stars as a weak signal.
- No Reddit, X or HN threads were successfully surfaced by search (results were blogs and vendor sites). Practitioner evidence below therefore comes from repos that document their own failures (strong), one Medium case study and a few SaaS blogs (weak).
- Search tool outputs are summarised by a model; wherever a claim rests on that I mark [S].

## 3. Official model prompt guides (primary sources, preferred over blog aggregators)

All fetched via search or WebFetch on 2026-10-05; details beyond the quoted formulas I did not check. Doc 12 section 5 already holds our dialect cards; these are for refreshing them.

## 4. What practitioners actually do (multi-agent AI film pipelines)

Convergent patterns across the repos I read (items 1-7) and the Medium/paper sources (items 24-27). Evidence strength in brackets.

1. **Role split mirrors a film crew**: director/story, production designer (continuity bible), DP (shot size, lens, one camera move), gaffer (motivated light), editor (durations, handles, cuts), sound, script supervisor/continuity. Seen in ai-film-crew [V], FilmAgent [S], the Medium pipeline [S]. For us: a lean version is director + DP/prompt writer + editor/sound + verifier. The gaffer and script supervisor duties can be checklist items rather than separate agents (my judgment).
2. **Lock before you generate**: canon frame, identity text block, master keyframe, scene geography, brand lock [V: items 1, 2, 7]. Everything downstream derives from the locked artifact, never from the previous shot's output.
3. **Stills before motion**: approve a still per setup, then animate; a rejected still costs one generation [V: item 1]. Some pipelines instead chain last-frame to next shot's image-to-video input [S: item 27]; the two strategies conflict (master-keyframe vs chaining) and no source tested them head to head. Doc 12 should pick one per scene type.
4. **One action / one beat per clip, 5-8 s, stitched in the edit** [V: items 1, 3, 5]. Failure documented with measurements in item 5 (H3 facial beats) and a demo in item 3.
5. **Describe, do not negate** [V: item 4], plus fix defects by changing the description or reference image, not by stacking "NO ..." lines.
6. **Critic loop with a rubric**: a separate agent scores each clip (aesthetics, technical fidelity, motion naturalness, artifact clarity, subject integrity per item 27) and returns ACCEPT/REVISE with the verdict hashed to what it reviewed (shotkit [V]). Item 3 adds "name the failure class and change exactly one thing before rerolling". Cap retries (item 27: 3). Our `verify.py` already follows the fingerprint idea.
7. **Gates and budgets**: lint scripts before any paid call (KeWang [V]), proxy-resolution renders before finals, cost routing and append-only logs (RandomNest [V]). KeWang's `verify_film.py` catches silent defects (runtime mismatch, audio leakage); we should measure final duration and loudness in `verify.py`, which doc 10 already lists.
8. **Human approval stays**: the open-source-cinema essay [S] and our own approval gate agree that the cut and taste decisions stay human.
9. **How they avoid incoherent or unrealistic shots** (summary): keep scenes in a master geography, specify eyelines and screen direction numerically, avoid combined camera moves, keep physics inside what 5-8 s can show, frame so countable things can be counted, supply clean reference images, and review stills first. Doc 12 section 4 already has the checklist; the sources above are the independent evidence for it.

Caveat: nearly all practitioner write-ups are for narrative shorts with human faces. Our cold open is 5-20 s inside an explainer with vector/illustrated scenes, so the identity and dialogue machinery will matter less than the one-beat rule, motivated light and clean seams.
